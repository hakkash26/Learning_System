# Personalized Java Programming Learning Path Recommendation — KG + Deep RL

A from-scratch Python implementation of the method described in:

> Zhou, L.-Y. & Wang, Y.-Y. *"Simulation of personalized Java programming learning
> path recommendation system based on knowledge graph and deep
> reinforcement learning."* Scientific Reports 15, 34554 (2025).
> https://doi.org/10.1038/s41598-025-17918-x

It implements every core mechanism described in the paper's Methodology
section — knowledge-graph construction, resource-to-knowledge mapping,
learner mastery modeling (direct feedback + graph propagation +
forgetting), the MDP formulation, and the **prune-then-select**
Q-learning-then-PPO recommendation strategy — and runs it end-to-end as
a self-contained simulation (synthetic learners standing in for the
paper's WeChat Mini Program deployment and its 200 real learners / 18,742
interactions, which are not publicly released).

**This is a simulation/reference implementation, not a re-run of the
paper's proprietary dataset.** Numbers you get from `run_simulation.py`
are internally consistent and reproduce the paper's *qualitative*
findings (the learned prune-then-PPO agent outperforms static/heuristic
baselines, especially on long-horizon return `G` and mastery gain `AMG`),
but will not numerically match Table 1 of the paper, since no public
dataset exists for that system.

### Scope notes / simplifications

- **Function approximators are linear**, not deep networks: `Q(s,a) = θᵀφ(s,a)`
  for the pruning network and a linear-softmax policy for PPO. This keeps
  the whole project dependency-free (numpy/pandas/matplotlib/networkx
  only — no PyTorch/TensorFlow) while preserving the algorithmic
  structure (TD learning + target network for Q; clipped surrogate
  objective for PPO). Swapping in an MLP is a drop-in change in
  `src/agents/features.py` + `src/agents/{q_learning,ppo}.py` if you want
  to scale this up.
- **Extended baselines from Table 3 of the paper (AKT, LightGCN, TA-RL,
  cDQN)** are not re-implemented; they're substantial models in their own
  right (attention-based knowledge tracing, graph convolutional
  recommenders, and full deep-RL path generators) that are out of scope
  for a single simulation script. `KG-H` (knowledge-graph-only heuristic,
  no learning) *is* included since it isolates the value of the graph
  structure by itself, matching the paper's own use of it as an ablation.
- **Learners and interaction logs are synthetic**, generated by
  `src/data_gen.py` (Beta-distributed diagnostic-test initialization) and
  a simple logistic "probability of answering correctly given current
  mastery" model in `src/environment.py`. This replaces the paper's real
  WeChat Mini Program logs.
- **Precision/Recall are operationalized** since the paper's "ground
  truth relevant set" comes from real user feedback we don't have; see
  the docstring at the top of `src/evaluate.py` for the exact proxy
  definitions used (usefulness = correct answer + meaningful mastery
  gain; recall = knowledge-point coverage of the pre-episode gaps).

## Installation

```bash
python3 -m venv .venv && source .venv/bin/activate     # optional
pip install -r requirements.txt
```

Requires only `numpy`, `pandas`, `matplotlib`, and `networkx`.

## Quick start

```bash
# smoke test (~2 seconds, tiny synthetic graph)
python scripts/run_simulation.py --quick

# full reference run (~90-100 seconds on a laptop CPU)
python scripts/run_simulation.py

# custom scale
python scripts/run_simulation.py --n-learners 200 --n-kp 36 --n-resources 140 --train-epochs 6
```

Sanity checks for the individual components (knowledge graph correctness,
mastery bounds, one training episode):

```bash
python scripts/test_sanity.py
```

## What `run_simulation.py` does

1. **Builds the knowledge graph** — hybrid expert + data-driven
   prerequisite edges, Jaccard-based semantic edges (θ = 0.3), and the
   resource → knowledge-point mapping matrix `M`.
2. **Generates a synthetic learner population** (default 120) with
   diagnostic-test-style initial mastery vectors, split 80/10/10 into
   train/val/test — mirroring the paper's dataset split.
3. **Trains the proposed agent** (`OursAgent`): at every step it forms
   the prerequisite-feasible, de-duplicated candidate set, prunes it with
   the Q-network, and selects the final action with the PPO policy; after
   each episode both networks are updated from the logged
   `(s, a, r, s')` transitions.
4. **Fits the baselines** (Markov Chain transition counts,
   item-item Collaborative Filtering) on the same training interactions;
   Rule-based and KG-H need no fitting.
5. **Evaluates all five methods** on held-out test learners and writes a
   Table-1-style comparison (`outputs/table1_performance.csv`).
6. **Sweeps Top-K ∈ [3,10]** and plots F1@K per method
   (`outputs/fig3_f1_vs_topk.png`), reproducing the shape of the paper's
   Figure 3.

### Example output (`--n-learners 120 --n-kp 24 --n-resources 90 --train-epochs 8`)

```

CF        0.511   0.606     0.553  0.159   0.185  4.343  0.152
Ours      0.547   0.551     0.547  0.161   0.190  4.324  0.210
Rule      0.504   0.502     0.501  0.153   0.180  3.759  0.235
MC        0.501   0.422     0.454  0.161   0.185  3.763  0.136
KG-H      0.469   0.435     0.450  0.168   0.189  4.701  0.131
```

Results vary run to run (different random seeds, small synthetic
population) — the qualitative pattern to look for is the proposed
prune-then-PPO agent being competitive with or ahead of the baselines on
ranking quality while typically leading on **AMG** (mastery gained per
learner), which is the long-horizon RL objective the paper is actually
optimizing for. Increasing `--n-learners`, `--n-kp`, and `--train-epochs`
generally sharpens this gap, at the cost of runtime.

## Extending this project

- **Bigger function approximators**: replace the linear `θᵀφ(s,a)` in
  `agents/q_learning.py` / `agents/ppo.py` with a small MLP (a minimal
  numpy MLP or a PyTorch module if you add that dependency).
- **Real data**: point `src/data_gen.py` at a real interaction log and
  replace `generate_learners` with a loader that reconstructs
  `(s(t), a(t), r(t), s(t+1))` tuples from logged events, as the paper's
  Section "Dataset construction and processing" describes.
- **Additional baselines**: implement AKT / LightGCN / TA-RL / cDQN
  (Table 3) as further modules under `src/agents/` following the same
  `choose(state, candidates, ...)` interface used by the existing
  baselines.
- **Statistical validation**: `src/evaluate.py` returns per-learner
  metrics; add the paired Shapiro–Wilk → t-test/Wilcoxon → BH–FDR
  pipeline described in the paper's "Statistical validation and
  interpretation" section using `scipy.stats` on those per-learner
  arrays.
